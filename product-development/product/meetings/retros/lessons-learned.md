# Lessons Learned

Rolling team-process lessons — the durable takeaways that outlive individual retros.

**Format:** one bullet per lesson, appended to the end (never re-sorted):

```
- YYYY-MM-DD — lesson (source retro link)
```

**Appended by:** `/weekly-review` (when the week surfaced a process lesson) and
`/context-update` (when a retro writeup or meeting artifact contains one).
Dated retro writeups live next to this file; link them as the source. If a
lesson has no retro doc yet, use a `[PENDING: path]` marker instead of a bare
claim.

Keep each lesson to one line. When a lesson stops being true, strike it with
`~~...~~` and a dated note rather than deleting — superseded lessons are part
of the record.

**Why one rolling file:** individual retro writeups capture what happened in a
sprint; this file keeps only the takeaways that should change how the team
works next quarter. Skills that plan work (`/weekly-plan`, `/pre-mortem`) read
this file — a lesson buried in a dated retro doc is a lesson lost.

**Scope:** *process* lessons — how the team works. Product learnings belong in
`product-development/product/decisions/` as hindsight notes, not here.
